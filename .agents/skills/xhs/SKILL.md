# XHS Rewriter

将任意长文改写为小红书笔记格式。只处理文字；配图交给 **visual** 或 **guizang-social-card-skill**。

## 产出落盘（正文 + 图）

```
content/projects/<content-slug>/
├── xhs.md           ← 本 skill 写的笔记正文
└── xhs/             ← 配图 skill 写的 3:4 系列（01-cover.jpg …）
    ├── 01-cover.jpg
    └── …
```

- 正文默认写入当前文章文件夹的 `xhs.md`（或 `derived/xhs-version.md`，与 derive 约定一致时二选一，优先问用户）。
- **禁止**把小红书图默认写到 `visuals/xhs/`。

## 平台数据洞察（62篇实测，2026-07-17 更新）

> 生成内容前先对照这里判断选题是否适合小红书。

### 什么有效

| 类型 | 均热 | 结论 |
|------|------|------|
| **可视化/图表**（AI画图/架构图/PPT/UI） | **3155** | 🔥🔥🔥 最强赛道，优先 |
| **数据分析**（职业洞察） | 801 | 🔥🔥 竞争少，值得投入 |
| **Agent开发**（有成果展示的） | 312 | 🔥🔥 保持 |
| **AI编程/Cursor**（成果图优先） | 165 | 🔥 可优化，改成成果展示型 |

### 什么无效（不要写）

- **模型资讯**（GLM-5发布/千问上线）→ 均热128，小红书用户不看新闻
- **纯原理教程**（Agent设计原理）→ 热度接近0，受众在B站
- **图文做复杂技术内容** → 视频均热1175 vs 图文190，6倍差距

### 爆款公式（从 TOP 5 反推）

```
Napkin图表（热度18178）= 时间对比痛点 + 工具名 + 视觉成果
架构图方案（热度5630） = 实用工具 + 效果图 + 可复制步骤
深度搜索（热度2525）   = 情绪词"震惊" + 冷门工具 + 使用场景
UI做法（热度1647）     = 精准受众痛点 + 可视化操作 + 工具对比
```

### 收藏是核心指标

顶级笔记的**收藏/点赞比≈1.5-1.7x**，即收藏多于点赞。
写法目标：让用户觉得"**以后会用到，先存着**"，而不是"好看就赞"。

## 内容类型路由（生成前先判断）

根据来源内容，匹配对应写法：

### A. 可视化产出型（优先推荐）

适用于：AI生成图/架构图/流程图/PPT配图/UI稿件

```
开篇：直接晒成果图或描述"成果对比"
     "以前手画要2小时，现在3步搞定"
正文：步骤化，每步配工具/操作
结尾：引导收藏 > 引导关注 > 引导评论
CTA："收藏这篇，下次用AI画图直接翻"
```

### B. 成果展示型

适用于：Cursor/Claude完成了某个项目，有截图/GIF可以展示

```
开篇：直接亮最终成果，不解释背景
     "用AI一个晚上搭完了这个系统"
正文：成果 → 如何实现（关键步骤）→ 踩坑点
结尾：引导评论"你用AI做过什么项目？"
```

### C. 职业/行业视角型

适用于：带有个人判断和行业观察的内容

```
开篇：反常识或情绪触发
     "做狗都不做数据分析师了" / "被XX震惊到了"
正文：数据佐证 → 个人观点 → 对读者的启示
结尾：引导讨论，提开放性问题
```

### D. 工具教程型（谨慎使用）

适用于：有明确操作步骤、受众清晰的工具上手内容

```
开篇：目标人群 + 能得到什么结果
正文：步骤清单（3-5步，每步有配图描述）
结尾：收藏导向 CTA
注意：纯文字步骤在小红书效果差，必须有配图或视频
```

## 前置步骤（每次必须）

1. 拉取线上策略：
   ```bash
   topics strategy --platform xhs --json > /tmp/xhs-strategy.json
   ```
   离线时用 `topics strategy --cached --platform xhs --json`。

2. Read `content/_config/platform-specs.json`，从 `platforms.xhs` 提取：
   - `noteMaxChars` → 1000
   - `titleMaxChars` → 20
   - `tagsCount` → 5-8个

3. 策略 JSON 包含：
   - `positioning`: 平台定位
   - `key_metric`: 核心指标（收藏/点赞比）
   - `content_routing`: 各类型均热和允许状态
   - `title_formulas`: 标题结构和黑名单

先判断选题是否适合小红书（对照 `content_routing` 的 allowed 状态），不适合就告知用户。

## 标题规则（≤20字，硬性约束）

**优先包含（三选二，以动态策略为准）：**
- emoji，通常放最前面；当标题已有足够强的具体结果或平台风格不适合时可省略
- 数字（3步 / 5个 / 1分钟 / 80%）；没有真实数字时不得编造
- 痛点或结果（省时间 / 被夸了 / 踩坑了 / 看完就会）

**好标题模式：**
```
🚀 [数字] 步 [具体结果]
😤 [踩坑场景]，终于搞明白 [核心概念]
💡 [工具名] 的 [数字] 个隐藏用法，[结果]
🔧 [时间] 学会 [技能]，[量化结果]
```

**黑名单词汇（出现就重写标题）：**
- "分享" / "介绍" / "简单聊聊" / "浅谈"
- "全面" / "深度" / "一文读懂"
- "教程" / "入门到精通"

## 正文结构

```
[开篇一句话]
点出痛点或直接给结论。不要从背景开始，也不要"今天来分享"。

[正文：3-5个要点]
每个要点可使用 emoji 或简短小标题，按内容密度与作者声音选择；不要为了格式让每段看起来一样。
具体内容，1-3句话。不抽象，不废话，有具体细节。

[结尾互动引导（必须有，选1种）]
- 你也遇到过这个问题吗？评论区聊聊 👇
- 你更想看哪个方向？评论告诉我！
- 有问题直接评论，我每条都看 📩
- 收藏备用，遇到这个问题翻出来看！
```

**要点 Emoji 对照（保持一致性）：**
- 💡 核心要点 / 洞察
- ⚠️ 注意事项 / 踩坑
- ✅ 验证有效的方法
- 🔧 工具 / 操作步骤
- 📌 总结 / 关键记忆点
- 🎯 目标 / 适用场景

**语言风格要求：**
- 句子不超过20字（小红书竖屏，超长断行很难看）
- 口语化：删掉"因此" "其次" "而言" "不难发现"
- 主动语态：不用"被广泛应用" 用"很多人在用"
- 有具体数字比空泛形容好："快很多" → "快了3倍"
- 第一人称或第二人称，不用第三人称叙述

## 标签规则（5-8个，两类混合）

**热门通用标签（每次选2-3个）：**
```
#AI工具 #效率提升 #程序员 #AI编程 #工作效率 #技术分享
```

**精准垂直标签（根据内容选3-5个）：**
```
#LangGraph #Claude #工作流自动化 #Python #开发者工具
#Obsidian #知识管理 #内容创作 #自媒体
```

标签放正文最后，每个 # 前空一格，不要换行分隔。

## 质检清单（输出前过一遍）

- [ ] 标题遵循 `topics strategy --platform xhs` 的当前公式，字数 ≤20；数字和 emoji 只在真实、适合时使用
- [ ] 开篇不是 "今天来分享" 或 "本文将介绍"
- [ ] 正文有清晰分段，不为统一格式强制每段加 emoji
- [ ] 无书面语（首先/其次/综上/不难发现/值得注意的是）
- [ ] 字数 200-500（超过 800 要压缩）
- [ ] 结尾有互动引导
- [ ] 标签 5-8 个，格式正确
