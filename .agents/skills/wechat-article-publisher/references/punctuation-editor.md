# 爱格标点校订流程

## 输入与输出

- 输入：`01-source.md`。
- 输出：`02-punctuation.md`。
- 审校记录：`qa/punctuation-diff.md`。
- 不生成 DOCX，不使用蓝色字体标记，不修改 Markdown 结构。

## 执行原则

先完整读取 `punctuation-style.md`，它是唯一标点规则源。不得另建一套标点规则，也不得从孤立句子或单个符号机械替换。

1. 完整阅读一节，暂不修改。
2. 忽略现有物理换行，识别完整思想的起点和终点。
3. 判断内部关系：紧密并列、快速列举、对照、递进、解释、转折或独立推进。
4. 判断各项属于词项、短分句、复杂分句还是完整观点。
5. 按 `punctuation-style.md` 选择标点。
6. 跨段复查 `不是……而是……`、`不仅……也……`、连续排比、时间递进和抒情结尾。
7. 复查冒号提示关系、引语内外标点和共享谓语列举。
8. 反向通读修改后的语意链。
9. 对低把握修改保持克制；两种写法都成立时保留原文。
10. 核验除标点外，文字、语序、Markdown 标记、段落和空白全部不变。

## 审校记录

每项修改使用以下结构，记录应用哪条既有规则，不创造新规则：

```markdown
## 01 · 第三节第 2 段

- 原文：不仅可以理解时间。 / 也可以来理解“志”。
- 修改：不仅可以理解时间， / 也可以来理解“志”。
- 依据：后句以“也”承接前句，前句不用句号截断。
```

审校记录不参与后续正文渲染。

## 验证

```bash
python3 scripts/validate_content.py --mode punctuation 01-source.md 02-punctuation.md
```

验证通过只表示非标点字符未改变。仍须逐项复核是否符合 `punctuation-style.md`、是否遗漏跨段结构、是否存在无充分依据的修改。
