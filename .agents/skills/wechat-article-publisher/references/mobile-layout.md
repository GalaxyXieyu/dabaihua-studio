# 微信公众号手机端语意分行

## 输入与输出

- 输入：`02-punctuation.md`；未执行标点模式时使用 `01-source.md`。
- 输出：`03-layout.md`，也是后续主题渲染的唯一冻结正文。
- 不生成 DOCX，不修改文字或标点。

## 三种结构

必须区分：

- Markdown 新段落：两个完整语意单元之间的分隔。
- `<br>`：同一语意组内部为了手机端节奏产生的软换行。
- `<!-- wechat:blank -->`：思想阶段、叙事转折或章节之间的额外留白。

不得把输入文件中的每个物理段落直接映射为最终硬段落，也不得用统一行距或段距代替语意分行。

## 工作流程

1. 完整阅读全文，识别标题、章节、小标题、正文语意组、排比组、问答组和结尾收束。
2. 先标出不能拆开的固定搭配、修饰关系、引语和专有名词。
3. 把共同完成一个判断的短段落合并成完整语意组。
4. 再从手机窄屏角度判断组内是否需要 `<br>`。
5. 拆分过长、密度过高或层次不清的段落，但只在自然语法节点处分隔。
6. 为完整思想、章节转换和叙事阶段设置段落或额外留白。
7. 单独处理章节序号、小标题、冒号后内容、长排比和结尾金句。
8. 从头模拟手机滚动，检查是否拥挤、碎裂、忽长忽短或留白失衡。
9. 核验忽略空白和布局标记后，字符与输入完全一致。

## 完整语意优先

以下结构通常属于同一语意组，应先合并判断，再决定是否用 `<br>`：

```text
问题往往不是我们没有力量，<br>
而是这些力量太容易耗散。
```

```text
使命也不再是生命之外的一项任务，<br>
而成为生命本身展开的方向。
```

条件／结果、提问对象／具体问题、行为／结果、`不是……而是……`、`不仅……也……` 都只是候选结构，不是强制断行公式。

不要：

- 按固定字数切行；
- 把每个逗号、分号或句号都当成换行点；
- 拆开固定搭配、引语或紧密修饰关系；
- 为追求上下等长损害语意；
- 把原稿“一句一段”原样放大成多个孤立硬段落。

## 排比呈现

- 短而整齐的排比：通常逐行连续排列，组内不增加空白。
- 单句较长的排比：可在自然节点使用 `<br>`，必要时才增加段间留白。
- 快速推进的排比：可以保持同一段，不必逐项断开。
- 排比结束后：用新段落或 `wechat:blank` 与下一思想分隔。

例如短排比可以连续呈现：

```text
时间是一种力量。<br>
注意力是一种力量。<br>
身体是一种力量。<br>
情感是一种力量。
```

## 标题与冒号

- 章节序号与小标题保持清晰层级；短标题能一行完整时不强拆。
- 章节大标题采用“序号—空一行—标题”的固定视觉结构；序号和标题均水平居中。
- 序号与标题在 Markdown 中保持为两个独立块；中间空行由 HTML 组件渲染，不向正文插入额外文字。
- 两行标题必须构成“完整判断／补充或结论”，不能只为视觉等长切开。
- 冒号后是短词时通常同行，如 `它真正带来的是：取舍。`
- 冒号后是完整金句或较长定义时，可以另起段落或使用 `<br>`。
- 本阶段不删除、新增或替换任何标点。

## 留白节奏

- 完整语意组内部保持连贯，不在每个短句后插入空白。
- 不同思想、叙事阶段或论述层次之间通常使用一个新段落；需要更强停顿时才加入 `wechat:blank`。
- 章节前后可以使用更强留白，但全篇保持一致。
- 避免连续大块空白、孤立单行和机械等距。

## 验证与报告

```bash
python3 scripts/validate_content.py --mode layout 02-punctuation.md 03-layout.md
```

未执行标点模式时以前件 `01-source.md` 验证。验证通过后还必须报告：

- 合并多少组原始物理段落；
- 拆分多少个过长段落；
- 新增多少处 `<br>`；
- 增减多少个 `wechat:blank`。

如果合并和拆分均为零，应重新确认是否真的完成了手机端排版，而不是只保留原稿结构。
