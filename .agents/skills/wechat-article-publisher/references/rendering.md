# 公众号 HTML 渲染

## 目标

把最近一个已验证的 Markdown 转换为可复制到微信公众号编辑器的 HTML。完整流程通常使用 `03-layout.md`；只执行渲染时使用 `01-source.md`。该文件是唯一冻结正文；渲染只改变表现层，不改正文字符，也不重新判断分行。

## 顺序

1. 读取并冻结当前已验证的 Markdown，不得再改标点、段落或 `<br>`。
2. 读取 `theme-index.md` 并选择一套主题。
3. 读取对应的 `theme-*.md` 和 `common-components.md`。
4. 识别标题、正文、引用、列表、代码、图片、表格及扩展 Markdown 标记。
5. 严格按主题配方映射现有结构，只从组件库取组件。
6. 运行内容合同与 HTML 合规校验。
7. 生成带复制按钮的预览页并检查手机窄屏节奏。

## 默认策略

默认关闭：标点归一化、自拟章节标题、英文标签、作者签名和 CTA。“一键完成”只授权自动执行工作流，不开放这些增强项；必须由用户逐项明确授权。

上层内容合同优先于主题文件。主题骨架中的“固定封面”“固定英文标签”“固定签名”“固定 CTA”“每段主动标关键词”等要求，在对应增强项关闭时全部降级：原稿没有就不生成，原稿已有才按主题样式渲染。

纯 `render` 模式默认关闭主动关键词选择，只渲染原稿已有的加粗、高亮和下划线。原稿的 `#` 标题必须在正文 HTML 中出现且只出现一次，除非用户明确要求把它作为公众号平台标题而不进入正文。

用户明确要求一级标题只作为公众号平台标题时，内容校验增加 `--ignore-source-title`；不得静默省略标题。

关键词下划线、高亮、卡片和章节编号属于视觉标记，可以开启，但不得改变原文字符。章节编号、目录文字等生成内容必须放在以下注释中，便于内容校验忽略：

```html
<!-- generated:start -->
<section>生成的导航或标签</section>
<!-- generated:end -->
```

## 扩展 Markdown

- `<br>`：渲染为同一语意组内部的软换行，不能拆成两个带段距的 `<p>`。
- `<!-- wechat:blank -->`：渲染为思想阶段之间的空白节奏块。
- `<!-- wechat:spacing before=N after=N -->`：转换成相邻段落的上下间距；数值来自 Word twip，只用于保持相对节奏。
- `<!-- wechat:paragraph align=... left=... first-line=... -->`：保留原稿的对齐和缩进；与主题冲突时，以原稿明确设置优先。

## 章节大标题

- 章节序号与紧随其后的章节标题必须分别渲染，并且都设置为水平居中。
- 序号与标题之间固定保留一个完整视觉空行；使用内联高度或间距组件实现，不生成可见文字，不改冻结 Markdown。
- 若标题组件包含装饰线，装饰线也应随标题居中。
- 本规则是统一排版合同；主题只能调整字体、字号、颜色和装饰风格，不能取消居中或标题前的一个空行。

## 平台约束

- 使用内联 `style`。
- 使用 `<section>/<p>/<span>/<strong>/<img>/<h3>` 等公众号兼容标签。
- 所有正文文字节点使用 `<span leaf="">` 包裹。
- 禁止 `<style>`、正文内 `<script>`、`<div>`、`class`、`id`、复杂定位、Grid、CSS 变量和外部字体。
- 代码、URL、英文专名内部标点保持原样。
- 图片使用 `max-width:100%;height:auto;display:block;margin:0 auto`。
- 同一篇文章只使用一套主题与通用组件，不跨主题拼接。
- 不得给所有段落机械套用同一个大段距来代替冻结 Markdown 的节奏。
- 不得把每个源物理行强制变成独立 `<p>`；段落、`<br>` 和留白必须一一对应。

## 交付文件

- `output.html`：干净正文片段。
- `output_预览.html`：浏览器预览和复制入口。
