# 爱格标点校订

## 总原则

先理解语意，再选择标点。不得从孤立句子或单个符号出发机械套用规则。

标点服务于四个层级：词项、分句、复句、完整观点。分行和分段只是版式线索，不自动代表语意结束，也不由本技能机械调整。

默认采取保守校订：仅修改把握度高、确实影响语意关系或阅读节奏的标点。两种写法均成立时保留原文。

## 必读参考

执行爱格文稿校订或解释判断标准时，完整阅读 [references/style-guide.md](references/style-guide.md)。其中记录经人工原稿—校订稿对比确认的规则、边界和范例。

若用户提供新的人工修改稿，将其视为更高优先级证据；逐项对比后更新判断，不得用既有规则反驳明确的公司编辑实践。

## 工作流程

1. 完整阅读一节，不立即改动。
2. 标出每个完整思想的起点和终点。
3. 判断内部关系：紧密并列、快速列举、对照、递进、解释、转折或独立推进。
4. 判断各项属于词项、短分句、复杂分句还是完整观点。
5. 按 `style-guide.md` 选择标点，而不是按现有换行逐句替换。
6. 单独复查跨行结构：`不是……而是……`、`固然……但……`、`不仅……也……`、连续排比、时间递进和抒情结尾；先忽略现有分行，按完整语意判断标点。
7. 单独复查列举形式：排比句使用逗号或分号，名词或名词性短语列举使用顿号；共享主语或谓语时，判断省略成分后能否还原为完整排比句。
8. 单独复查冒号是否真正提示后文，以及引语结束后外层句子是否仍在继续。
9. 反向通读修改后的语意链，确认停顿层级自然。
10. 核验除标点外的文字、分行和段落完全不变。若用户同时要求公众号排版，标点校订完成后再使用公众号推文排版技能。
11. 对 DOCX 中每处实际修改的标点及其前一字统一标为纯蓝色（`#0000FF`），便于人工复核；蓝色前一字只用于定位，不代表文字被修改。

## 修改边界

- 不改变文字、措辞、语序、写作风格或事实内容。
- 不主动给普通概念增加引号。
- 不机械统一逗号、顿号或分号。
- 后句以“而、也”承接前句时，前句使用逗号，不用句号截断；“但、却”等其他转折承接词仍结合上下文判断。
- 保留原稿段落和分行。分行属于移动端视觉排版策略，不是标点硬规则；除非用户同时授权排版，否则不拆分、合并或新增空白段落。
- 遇排比句时，在结构较短、关系紧密、处于同一层级的排比句之间使用逗号；在内部已有逗号、结构较长或层级较重的排比句之间使用分号。共享主语的短动词结构，只要补全主语后分别构成完整判断，也按排比句处理。完整排比句、独立动作句和判断句不使用顿号。
- 遇名词或名词性短语列举时使用顿号。若多个短项共享同一谓语，且实际列举的是同类对象，也可按名词性列举处理。
- 引语后没有同一语意继续时，不在后引号外额外添加句号或逗号；外层句子尚未结束时，按外层句法在后引号外使用逗号等标点连接后文。
- DOCX 校订默认采用颜色标注：每处实际修改的标点及其前一字统一标为纯蓝色（`#0000FF`）。不得扩大到整个词语、句子或段落；前一字只作视觉定位。若标点位于段首或前面没有文字，只标记标点。若用户明确指定其他非黑色颜色，则按用户指定执行。

## DOCX 处理

同时使用文档处理 Skill，保留原始样式、分节、段落、分行和运行格式。优先在原标点所在 run 内进行局部替换，不重写整个段落。必要时拆分 run，使颜色只作用于修改标点及其前一字；除字体颜色外，这两个字符应继承原位置的字体、字号、粗斜体等格式。

生成文件后必须：

1. 对比原稿与输出，确认字符差异仅为获准的标点，文字、分行和段落未变；确认每处修改标点及其前一字均使用同一种非黑色颜色，未扩大误标范围。
2. 渲染 DOCX 并逐页检查版式；若渲染器缺少中文字体，使用可用的系统预览补充检查，并明确记录限制。
3. 输出新文件，不覆盖原稿。

## 原稿与人工稿对比

需要学习人工校订时，可运行：

```bash
python scripts/compare_punctuation_docx.py 原稿.docx 人工校订稿.docx
```

脚本只负责提供差异证据。必须结合完整上下文解释每一处变化，不能依据替换次数自动推导规则。

## 交付说明

简要说明修改数量、标注颜色和主要语意关系。蓝色前一字不得计入文字修改数量。不要声称所有改动都来自国家标准；应说明本技能优先遵循爱格经人工确认的语意与节奏习惯。
