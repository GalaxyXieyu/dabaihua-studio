# Content Derive

从 Master 长文一次性衍生所有平台的文本版本。
原则：从复杂到简单，每一层从上一层提炼，不重新写。

## 前置步骤（每次必须）

1. Read `content/_config/platform-specs.json`
2. 拉取线上策略：
   ```bash
   topics strategy --section derivation_order --json > /tmp/derive-order.json
   topics strategy --platform gzh --json > /tmp/gzh-strategy.json
   ```
   离线时用 `topics strategy --cached`。
3. Read 用户提供的 Master 文章（如未指定，询问路径）
4. 确认用户要生成哪些平台版本（默认：全部，按 `derivation_order` 顺序）

## 衍生顺序与规则

衍生顺序固定：视频脚本 → 公众号版 → 小红书版 → X Thread
每一步从上一步提炼，不跳步。

---

### 版本 1：视频脚本（从 Master 改写）

字数目标：1500-2500字（对应5-8分钟视频）

规则：
- 去掉所有 Markdown 格式（#标题 **粗体** `代码` 等）
- 口语化：去掉书面语，改成说话的方式
  - "通过分析..." → "我发现..."
  - "因此可以得出..." → "所以我认为..."
  - "综上所述" → 直接说结论
- 段落 = 镜头，每段大约30秒，自然断点
- 结构：
  ```
  [开头10秒：直接说这期讲什么，你能学到什么]
  [正文：每个要点一个段落，有举例/截图提示]
  [结尾：总结+引导关注/私信]
  ```
- 在需要展示内容的地方加 `[截图提示：xxx]` 注释
- 不要 emoji，不要 markdown 格式

### 版本 2：公众号版（从 Master 微调）

#### Step 1：判断内容类型

先识别 Master 属于哪种，决定改写力度：

| 类型 | 改写力度 | 重点 |
|------|---------|------|
| **工具教程/系列课** | 最小改动 | 标题加搜索词，保留完整步骤，加系列 footer |
| **实战分享/踩坑** | 轻改动 | 强化 Hook，突出亲身场景，加私域引流 |
| **判断型/为什么选X** | 中改动 | 标题改成强立场，开头从结论/判断切入 |
| **方法论总结** | 中改动 | 每节加可执行小结，结尾不要"综上所述" |
| **热点借势** | ⚠️ 检查时效 | 距离热点发布超过48小时？→ 加亲测角度，否则不发 |

#### Step 2：标准调整项（每次必做）

- 标题 ≤64字（`content/_config/platform-specs.json` 的 `platforms.gzh.titleMaxChars`），且符合内容类型路由的标题公式
- 开头前150字：直接切入场景/问题/结论，不铺垫背景
- 文末加私域引流句（见模板）

#### Step 3：易读性调整

公众号版必须继承 writer 的“长文易读性合同”，不能只做标题和字数适配：

- 1500-3000 字正文通常保留 3-6 个有信息量的 H2 小标题。教程、对比和方法论可按真实步骤增加，叙事文可减少。
- 普通段落以 2-5 句为主。连续出现约 150 个汉字以上的文字墙时，按事实、判断或结果拆段。
- 每节开头说清要解决的问题，结尾留下判断、后果或下一步。只扫标题和每节首句也能复述文章主线。
- 技术术语第一次出现时先解释用途。代码块前说明解决什么问题，代码块后只解释关键点。
- 列表、表格和代码用于降低理解成本，不能堆更多信息。表格超过 6 列或单元格成为小作文时，改为分段比较。
- Master 里的完整研究证据只保留会改变结论和选择的部分，其余放来源、附件或延伸阅读。

#### Step 4：系列 footer 注入（如果是系列文章）

检查 Master frontmatter 里有没有 `series` 或 `part` 字段，有则在文末自动插入：

```markdown
---
**[系列名] 全系列导航：**
- 第0篇 → [大纲导读链接]（推荐先看）
- ← 你现在看的：第N篇 · [当前标题]
- 第N+1篇 → [下一篇标题/预告]（更新中）
```

> 注：链接在草稿阶段先写占位符，发布后回填真实链接。

#### Step 5：字数控制

- 超过 4000 字 → 询问用户是否拆分成两篇
- 低于 800 字 → 提醒可能深度不够

私域引流模板（文末选一个）：
```
想深入交流这个话题，欢迎加我微信：[微信号]
更多实战内容，关注这个公众号，每周更新。
```

### 版本 3：小红书版（从公众号版提炼）

直接调用 xhs 规则（Read `.agents/skills/xhs/SKILL.md`）

提炼逻辑：
- 从公众号版找出核心3-5个要点
- 保留最有共鸣的1-2个案例/数据
- 去掉所有背景铺垫（用户已知）
- 开头直接从最痛的痛点或最强的结论开始

---

### 版本 4：X Thread（从小红书版再提炼）

字数：每条推文 ≤250字（留余量，platform-specs 限制280）
条数：5-7条
从 `content/_config/platform-specs.json` 的 `platforms.x` 获取每条字数和推荐条数：
Hook → 核心内容(3-5条) → 总结 → CTA

规则：
- 第1条：最强洞察/结论，直接给答案，不铺垫
- 第2-6条：每条一个要点，带数字编号
- 最后1条：总结 + 引导（关注 / 点击 / 回复）
- 语言：中英混合 or 纯英文都可以（根据 Master 语言）
- 不用 emoji 密集，但可以适量（1-2条一个）

X Thread 格式：
```
1/ [Hook - 最强的那句]

2/ [要点1]

3/ [要点2]

...

7/ [总结 + CTA]
---
```

## 执行方式

### 全量衍生（默认）

用户说"帮我衍生这篇文章"时：
1. 依次生成 4 个版本
2. 每个版本生成完，先显示，然后继续下一个
3. 全部完成后：
   - 汇总字数统计
   - 列出各版本保存路径建议

### 单版本衍生

用户说"只要小红书版"时，跳过其他版本，直接输出指定版本。

### 保存路径（询问用户确认后写入）

```
content/projects/<content-slug>/derived/
├── video-script.md     ← 版本1
├── gzh-version.md      ← 版本2（如果和 master 有实质改动）
├── xhs-version.md      ← 版本3
└── x-thread.md         ← 版本4
```

## 质检清单（衍生完成后）

- [ ] 视频脚本：1500-2500字，无 markdown 格式，有截图提示
- [ ] 公众号版：标题≤64字，有 hook，有私域引流，已通过 qa L5 可读性检查
- [ ] 小红书版：按 xhs 规格检查
- [ ] X Thread：5-7条，每条≤250字，第1条是最强洞察

## 时间估算

全量衍生（4个版本）约 20-30 分钟人机协作时间。
小红书版是时间最长的（需要大幅压缩和重写风格）。
