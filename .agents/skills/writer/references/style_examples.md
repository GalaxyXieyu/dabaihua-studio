# DeepSeek Harness 很好，但你现在不用学

8 月 13 日，DeepSeek Harness 发布后，很多群都在转一句话：Agent 时代的安卓来了。

它被称为“开源版 Claude Code”，也有人认为，DeepSeek 可能借此重塑 Coding Agent。打开官方仓库，能看到三个关键词：v0.1、MIT 开源，以及 everything is a plugin。

项目确实很有意思。但我的第一反应不是赶紧学，而是：又有一批人要开始焦虑了。

大多数人使用 AI，是为了尽快完成一项具体工作。比如下班前整理一份会议记录、生成日报，或者修改一段代码。对他们来说，工具就好像一家已经营业的餐厅，点单之后直接上菜。

Harness 的定位却更接近一间可以自己装修的厨房：你可以更换设备、调整流程，甚至重新设计整套出餐系统。对开发者来说，这种自由非常有价值；对只想马上得到结果的人来说，它意味着额外的学习和维护工作。

所以我的判断很简单：Harness 值得关注，但现在不必急着学。

## Harness 的核心定位是 Agent 运行时

简单说，Harness 是让 Agent 持续运行的“骨架”。模型、工具、技能、会话、沙箱、存储、循环、调度和 UI，都被拆成可以单独替换的插件，再通过 Cordis 进行组合和协作。

这意味着它提供的不是一个固定形态的助手，而是一套可以被开发者重新组装的 Agent 基础设施。你可以替换模型，调整工具调用方式，修改权限策略，甚至重新设计 Agent 的运行循环。

它的价值不只在于“能不能完成任务”，还在于“任务是怎样被完成的”。开发者可以直接研究计划如何生成、工具如何调度、上下文如何管理，以及失败后如何重试，并在此基础上写插件、改流程、做实验。

官方提供了不同运行模式，包括功能完整的编码 Agent、可以让模型用 TypeScript 组合工具调用的 PTC 模式、用于基准测试的极简模式，以及用于实验插件和 Agent 预设的创造模式。

从产品定位看，Harness 更像一个可编程的 Agent 运行时，而不是成熟的 Claude Code 或 Codex 替代品。

## 插件化提高了自由度，也提高了使用门槛

“万物皆插件”听起来很有吸引力，但插件化解决的主要是开发者的可重组问题，不是普通用户的上手问题。

它至少带来三类成本。

第一是学习成本。使用者需要理解 Cordis 的插件机制，知道模型、工具、会话、循环和权限如何协作。普通用户如果只是想整理资料或生成日报，可能还没有开始使用，就要先理解一套新的运行结构。

第二是维护成本。Harness 目前仍处在 developer preview 阶段，官方已经明确提示，未来会出现破坏兼容性的变更。今天可用的配置、插件和工作流，下个版本可能需要重新调整。

第三是生态成本。官方路线通常需要 Node.js 22 以上环境，并处理依赖、API Key、workspace、preset 和权限。社区虽然已经出现一些桌面版封装，但它们并非 DeepSeek 官方产品，更新节奏、安全审核和长期维护都需要用户自行判断。

这也是“装修厨房”这个比喻最关键的地方：你获得了调整设备和流程的权利，同时也要承担设计、维护和排错的责任。自由不是免费的，它通常以专业能力和时间投入为代价。

相比之下，Claude Code、Codex 或 WorkBuddy 更强调开箱即用。它们把环境、依赖和大部分底层复杂性封装起来，用户可以直接进入工作状态。两种路线没有绝对的高下，只是服务于不同需求。

## Harness 目前更适合三类用户

第一类是正在开发 Agent 产品的人。你可能需要更换模型、工具、循环或 UI，也可能需要为不同业务设计不同的权限和执行流程。对你来说，Harness 的插件化不是额外负担，而是产品能力的一部分。

第二类是研究 Agent 内部机制的人。你希望理解任务拆解、上下文管理、工具调度和执行循环，而不是只通过一个封装好的界面调用模型。Harness 可以作为一份可运行、可修改的研究材料。

第三类是有编程基础、时间充足，并且能够接受预览版不稳定的人。你愿意跟进更新、阅读源码、处理兼容问题，也清楚早期项目的价值和风险并存。

这三类人的共同点是：他们关心的不只是“能不能用”，还关心“能不能改、能不能研究、能不能嵌入自己的系统”。

如果你的需求只是写代码、整理资料、生成周报或处理日常办公，现有的开箱即用工具大概率已经够用。把它们的高级功能用明白，把自己的工作流程跑顺，通常比学习一个新框架更快产生回报。

## 为什么我自己不急着学

每次有新框架出来，我都会拿几个问题过一遍，再决定投入多少。

它解决我真实的瓶颈吗？我不换模型、不换工具的话，“可定制”对我就是纯负担。它够稳定吗？预览版意味着今天写的配置，下个版本可能直接作废。生态起来了吗？现在能抄的模板还很少，踩过坑的人也不多，配置、教程很多东西要自己补。成本能接受吗？学习时间、维护精力、陪它改版的折腾、API 费用，免费软件一样也不省。

套在 Harness 身上，稳定和生态这两条明显不过。所以我的结论还是开头那句：可以学，不用急着学。
