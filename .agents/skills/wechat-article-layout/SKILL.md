# 公众号推文排版

## 核心原则

以公众号手机界面的工整、舒适和易读为目标。分行与留白是视觉编辑，不是语法硬规则；不得从固定句式机械推导唯一断行。

保持所有非空白字符完全不变，包括文字、标点、数字、英文、引号和标题内容。只调整段落边界、换行和空白段落。若用户同时要求标点校订，先使用 `aige-punctuation-editor` 确定标点，再执行本技能。

把语意作为安全边界，把移动端视觉作为最终取舍：同一语法结构在不同位置可以采用不同排版。

## 工作流程

1. 完整阅读全文，识别标题、章节、小标题、正文语意段、排比组、问答组和结尾收束。
2. 先标出不能拆开的固定搭配和紧密语法成分，再标出适合考虑分行的自然节点。
3. 合并被原稿分行错误割裂、但视觉上适合连贯阅读的同一语意。
4. 拆分手机端过长、密度过高或结构不清的行，使上下行长度和重心更协调。
5. 用空白行区分完整语意段；在同一排比组内部保持连续，过长时才酌情增加空白行。
6. 单独处理章节序号、小标题、冒号后内容、长排比和结尾金句。
7. 从头模拟手机端滚动阅读，检查是否出现拥挤、碎裂、忽长忽短或留白失衡。
8. 核验忽略空白后的字符序列与原稿完全一致。

## 分行判断

### 视觉优先，不设固定断行公式

条件／结果、提问对象／具体问题、行为／结果、`不是……而是……`、`不仅……也……`、`如果……那么……`等结构，都是适合考虑分行的位置，但都不是必须分行的规则。

长句可在自然语法节点处分行，例如主语或话题之后、条件或原因之后、转折承接处、结论之前；只有在手机端更工整、舒适时才这样做。

不要：

- 按固定字数切行；
- 拆开固定搭配、专有名词、引语或紧密修饰关系；
- 为追求上下等长而损害语意；
- 把每个逗号、分号或句号都当作必须分行的位置；
- 把分行偏好反过来当成标点判断依据。

### 合并被割裂的同一语意

原稿“一句一段”不一定适合手机端。若几个短句共同完成一个紧密判断，可合并为同一段或同一行组，但不得修改标点。

排版只处理空白。如果合并后需要更换标点才能成立，应先交给标点校订技能处理，不能在本技能中顺手改标点。

## 排比呈现

先识别一整组排比，再选择视觉密度：

- 短而整齐的排比句：通常连续逐行排列，组内不加空白行。
- 单句较长的排比：可拆成上下两行，或在各排比句之间酌情增加空白行。
- 快速推进、总结归纳或刻意制造密集节奏的排比：可保持同段，不必逐项留白。
- 一组排比结束后：用空白行与下一语意段分隔。

是否增加空白行，取决于单句长度、页面拥挤程度、阅读停顿和整组视觉效果，不由分号本身决定。

例如，较长排比可呈现为：

```text
如果我真的知道家人重要，
我会给他们最好的注意力；

如果我真的知道身体重要，
我不会不断随着欲望去透支它；
```

如果连续排列更工整，也可以不加中间空白行。

## 标题与章节

- 章节序号可单独成行，并与正文形成清晰留白。
- 小标题可根据手机端宽度拆为一行或两行。
- 两行标题常呈现“上位判断／补充或结论”，但这只是常用视觉方案。
- 标题较短且一行完整时，不强行拆分。
- 本技能不删除或新增标题标点；标题标点需要调整时，先使用标点校订技能。

示例：

```text
使命不是牺牲爱
而是让爱进入时间
```

## 冒号后的排版

先沿用已经确认的冒号，不在本技能中改动它。

- 冒号后是很短的词语或短语时，通常保持同一行，例如：`它真正带来的是：取舍。`
- 冒号后是完整的金句、定义句或较长的强调内容时，可以另起一行。
- 冒号后只是普通解释、说明或列举时，通常不因冒号单独分行。
- 最终仍以手机端是否工整舒适为准，不把以上倾向写成硬规则。

## 留白节奏

- 一个完整语意段内部保持连贯，不在每个短句后插入空白行。
- 不同思想、叙事阶段或论述层次之间通常保留一个空白行。
- 章节序号、小标题与正文之间可使用更强留白，但全篇保持一致。
- 过长排比可酌情逐项留白；短排比避免过度松散。
- 避免连续大块空白、孤立单行和页面密度忽高忽低。

## DOCX 处理

同时使用文档处理技能，保留原稿字体、字号、颜色、粗斜体、分节、页边距及其他样式。只通过拆分或合并段落、插入或删除空白段落来调整版式；不要重写文本。

若拆分包含多种 run 样式的段落，按字符位置保留原 run 格式。若合并段落，保留各文本片段原有格式，不把整段统一成单一样式。

生成文件后必须：

1. 对比原稿与输出，确认去除所有空白字符后，两稿字符序列完全一致。
2. 确认未改变任何标点、文字、数字、英文或引号。
3. 渲染 DOCX 并逐页检查版式；若常规页面渲染不能代表手机宽度，额外按窄屏思路复核行长、留白和滚动节奏。
4. 输出新文件，不覆盖原稿。

## 检查清单

- 是否先理解全文结构，再调整分行？
- 是否把常见句式误当成强制断行规则？
- 每一处拆分是否同时满足语意安全和手机端视觉改善？
- 是否合并了被原稿错误割裂的紧密语意？
- 排比句之间的空白是否与句长和阅读节奏匹配？
- 小标题是否简洁、工整且不过度拆分？
- 冒号后的短词是否避免不必要的另起一行？
- 空白行是否划分语意段，而不是机械跟随标点？
- 是否存在过碎、过密、忽长忽短或留白失衡？
- 除空白外的所有字符是否完全不变？

## 交付说明

简要说明调整了多少处分行、合并和空白段落，并说明这些是移动端视觉优化，不是标点或语法修改。
