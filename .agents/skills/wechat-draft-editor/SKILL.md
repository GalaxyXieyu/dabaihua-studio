# 公众号文稿去 AI 化

把原稿改到像作者自然写出来，而不是把它改得更口语、更热闹或更像另一位作者。先处理内容结构，再处理句子。

## 开始前

1. 读取原稿全文，不按关键词直接批量替换。
2. 读取 `content/_config/author-voice.md`。若用户另给真实样稿，以用户样稿为更具体的声音依据。
3. 需要检查逻辑和可读性时，读取 `.agents/skills/qa/SKILL.md`，只使用 L3、L4、L5 中与文本内部逻辑、阅读路径和表达负担有关的规则；排除观点支撑、案例充分性、材料密度和事实证据检查，也不要自动套用发布规格、封面、私域钩子或禁用标点规则。
4. 把事实、数据、时间、人物、引用、作者经历、观察范围、结论、命令、代码、参数、链接和专有名词视为作者已经确认的内容，不质疑真伪或证据是否充分。
5. 只检查文本内部是否自相矛盾、指代不清或关系断裂。除非用户明确要求事实核验或研究，不检查经历是否真实、个案能否代表群体、观点是否有外部材料支撑。
6. 修改前圈出事实锚点：数字、比例、时间、人物、组织、产品、职位、引用、链接、案例步骤、角色数量、分工、事件结果和业务口径。后续只能优化这些内容周围的表达，不能替换锚点本身。

输入是 DOCX、PDF 或其他格式时，先抽取为 Markdown 工作正文；审校只修改正文内容，不顺带调整主题、视觉排版或发布状态。

## 选择模式

- 用户只说“检查、审稿、看看问题”时，使用**诊断模式**，不直接改原稿。
- 用户说“修改、润色、去 AI 味、改得自然”时，使用**修改模式**。
- 用户同时要求检查和改稿时，先给精简诊断，再给完整修改稿。

## 审校维度

### 1. AI 腔、翻译腔和过度书面腔

判断句子是否在传递信息，还是只在报幕、搭台、制造转折或假装深刻。重点检查：

- 预告后文，却没有增加阅读价值；
- 用否定式承诺包装普通内容；
- 省略主语或宾语，留下翻译式、标签式短句；
- 先替读者安排一种笼统认知，再开始解释；
- 用连接词代替真实的因果、递进或转场；
- 连续出现工整对仗、机械三段式、抽象总结和宣传性判断；
- 为了“像真人”硬加口头禅、疑问句、自嘲、经历或情绪。

对用户指出的表达按语境处理：

| 表达症状 | 判断 | 修改方向 |
|---|---|---|
| “接下来我会从……” | 多数是在宣布写作动作，读者仍不知道具体信息 | 删除报幕，直接进入事实、问题或小标题；只有确有复杂阅读路线时才简短交代 |
| “这一章不说……，直接告诉你……” | 常用否定承诺制造爽感，正文却仍在重复铺垫 | 直接写结论或操作；若前文确需划定范围，具体说明不覆盖什么及原因 |
| “不陌生” | 常是缺少主体或具体语境的空泛熟悉感 | 写清谁对什么熟悉；无法具体化且不影响信息时删除 |
| “起初，我们很容易把这理解成……” | 常替所有读者预设同一种认知，也带翻译式叙述腔 | 改成作者自己的判断、具体观察或文中已经出现的认知变化；不把作者视角无故扩大成“我们” |
| “于是……” | 词本身没有错；连续用于段首或前后无因果时，会成为机械转场 | 因果真实时保留或直接写结果；关系不成立时改成时间、条件、对比等准确关系，或直接另起段 |

不要执行机械替换。同一句式在引用、必要范围说明或真实叙事中可能成立；判断它是否承担了不可替代的信息功能。

### 2. 逻辑与易读性

逐段确认：

- 每一节只推进一个主要问题，上一段能自然引出下一段；
- 现象、判断、原因、例子、结论和行动建议没有互相冒充；
- 因果、递进、转折关系在文本内部成立，不把时间先后写成因果；不审查外部证据是否足以支持作者观点；
- 代词、主语和指代对象不造成实际歧义。个体与群体、单数与复数之间的自然视角切换可以保留，不因形式变化本身判错；
- 根据用户说明、作者声音和原稿专业程度判断目标读者的知识基线；只解释会阻碍目标读者理解主旨，或在本文中有特殊口径的术语；
- 长句没有塞入过多条件、转折与结论；
- 删除连接词后，段落关系依然成立；如果不成立，先补逻辑，不靠“于是、因此、换句话说”粘合；
- 只读标题、小标题和每节第一句，也能复述文章主线。

不要把“易读”理解成一律改成短句。保留自然的长短变化，优先修复需要回读、歧义或信息层级混乱的句子。

不要见到术语就追加“也就是”“这里指的是”“意思是”等教学式解释。目标读者日常使用的行业词、公司名、产品名和岗位名通常直接保留。作者自定义的概念、必须统一计算口径的指标、可能产生多种理解的核心比喻，以及用户明确要求说明的词，才需要用上下文简短说清。

去 AI 化不等于压缩信息。原稿中的人物、动作、过程、时间成本、具体后果和自然比喻，如果承担了解释作用，应优先保留。抽象观点后已有清楚案例时，不要用更概括、更标准的行业表达替换它；每个关键分点至少保留足以说明“发生了什么、为什么、造成什么结果”的内容。

### 3. 语意重复

同时检查四类无功能重复：

1. **字面重复**：相邻句反复使用同一表述。
2. **近义重复**：换了词，但结论、因果或解释没有新增信息。
3. **结构重复**：开头预告一次、正文展开一次、段尾再总结一次。
4. **材料重复**：两个例子证明同一件事，第二个没有提供新边界或反例。

判断重复时比较两处内容承担的功能，不只比较话题或词义是否接近。保留：

- 在不同论证节点承担不同作用的边界说明，例如先说明“无法确定具体原因”，后面再提醒“不要给所有人套统一答案”；
- 从个体场景切换到群体观察时必要的视角重述，只要指代仍然清楚；
- 用于建立节奏、回扣标题、首尾照应或强化核心意象的动作和词语复现，例如开头与结尾再次出现“一层层包好”“放回固定位置”；
- 前后形成认知变化、对照或情绪递进的重复。

只有两处承担相同功能、后一处没有推进判断、边界、行动或叙事时，才删除或合并。不要用同义词轮换掩盖真正的重复，也不要为了压缩而破坏叙事回环。

## 修改顺序

1. 记录原稿的事实锚点。
2. 删除或合并语意重复。
3. 调整段落顺序，补齐逻辑断点。
4. 删除报幕、空泛转场和机械结构。
5. 改写翻译腔、书面腔和费解句子。
6. 对照原稿逐项确认事实锚点、观点、观察范围和作者声音没有改变。
7. 通读修改稿，确认局部修改没有产生新的重复、指代问题或解释不足。

结构调整优先于同义词替换。若一段同时存在重复和措辞问题，先决定它是否应该存在，再润色句子。

## 事实锚点检查

长文或含有数据、案例、引用时，在交稿前运行：

```bash
python3 .agents/skills/wechat-draft-editor/scripts/check_content_anchors.py 原稿.md 修改稿.md
```

脚本对比数字与数量、时间、URL、引用内容和英文专有名词。退出码为 `1` 表示存在变化，必须逐项核对；这只是报警，不自动修改正文。脚本无法可靠识别所有中文人名、案例步骤、角色分工和语义强度，仍需人工对照。

## 编辑边界

- 不凭空添加作者经历、数据、来源、观点、情绪或案例。
- 不用模型记忆或未经用户要求的外部信息替换原稿中的数字、人物、时间、案例和来源；即使新信息看起来更完整或更可信，也先保留原稿。用户明确要求事实核验或研究时，才单独核验并说明来源。
- 不为了让案例更顺畅而补写具体细节、替换提问、改动角色分工，或把原稿案例换成更“典型”的例子。
- 默认原稿中的经历、事实、群体观察和判断已经作者确认；不要求作者证明真实性，不审查证据跨度，也不建议仅因缺少外部证据而降低原稿判断强度。
- 只有文本内部出现直接矛盾、缺失对象或无法理解的跳转时，才从表达角度指出；不要把内部逻辑检查扩大为事实核验。
- 发现数量、人物、时间、分工或口径不一致时，不猜测正确答案，不静默选择一种改法。若原稿没有唯一、无歧义的答案，保留原文并列为作者确认项。
- 不把作者的明确判断改成面面俱到的中性总结。
- 不为了去 AI 味而故意制造残句、俚语、网络梗或不完整逻辑。
- 不擅自改变事实强度，例如把“可能”改成“必然”。
- 不修改引用原话；如引用本身有问题，只做标注。
- 不顺带执行标点专项、移动端分行、公众号排版、配图或发布。
- 不以“内容是否真实”“有没有更多案例”“能否代表群体”为由提出作者确认问题。只有表达存在多种合理走向、且不同选择会改变原意时，才请作者选择。

## 输出

### 诊断模式

按影响程度列出问题，每项包含：原文定位、问题类型、为什么影响阅读、建议改法。合并同类小问题，不输出关键词命中清单。

最后给出：

- 总体判断：可直接修改 / 需要调整结构 / 暂无需要修改的内容语言问题；
- 最优先处理的 1–3 个问题；
- 必要时列出不超过 3 个需要作者选择的表达取舍；不要提出事实核验或补证据问题。

### 修改模式

依次输出：

1. 修改后的完整正文或修改后的文件；
2. 改动摘要：删了哪些重复、调整了哪些逻辑、处理了哪些语言腔调；
3. 必要时列出不超过 3 个需要作者选择的表达取舍；不要提出事实核验或补证据问题。

若修改范围很小，可用“原句 → 修改句 → 原因”呈现；长文不要输出逐句流水账。

## 交稿前检查

- [ ] 没有依靠报幕句推动文章。
- [ ] 没有用否定式承诺反复制造语气。
- [ ] “不陌生”“我们很容易认为”等表达有明确主体和具体语境。
- [ ] “于是”等连接词对应真实关系，而非段落粘合剂。
- [ ] 相邻段落没有重复同一结论、因果链或例子。
- [ ] 没有把不同功能的边界说明误判为重复。
- [ ] 没有把清楚的单复数视角切换误判为指代错误。
- [ ] 没有删除服务于首尾照应、核心意象或叙事节奏的复现。
- [ ] 文章主线可以通过标题、小标题和首句复述。
- [ ] 没有为了简洁删除支撑抽象观点的场景、动作、过程或具体后果。
- [ ] 术语解释符合目标读者基线，没有把专业文章改成入门科普。
- [ ] 每处修改都保留了原稿的事实、观点与语气强度。
- [ ] 没有新增未经作者提供的经历、情绪、数据或观点。
- [ ] 数字、比例、时间、人物、组织、产品、职位、引用、链接、案例步骤、角色数量、分工、事件结果和业务口径均已逐项对照。
- [ ] 原稿中的内部不一致没有被猜测性修复；需要选择的地方已保留并列为作者确认项。
- [ ] 含数据、案例或引用的长文已运行事实锚点检查脚本，并人工处理所有报警。
- [ ] 没有质疑原稿经历的真实性、证据跨度或群体观察的成立范围。
