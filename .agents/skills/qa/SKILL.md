# Content QA

发布前质检。两个模式：

- **规格检查**：对照 platform-specs.json 检查字数/标题/格式
- **文章质检**：L1-L5 五层自检，从硬规则、活人感到长文可读性全覆盖

---

## 前置步骤

1. Read `content/_config/platform-specs.json`
2. 拉取线上策略：
   ```bash
   topics strategy --section banned_patterns --json > /tmp/banned.json
   ```
   离线时用 `topics strategy --cached --section banned_patterns --json`。
3. Read 要检查的内容
4. 确认：是只做规格检查，还是做完整的 L1-L5 质检？

默认：发布前做**规格检查 + L1-L5 全量质检**。公众号长文、知乎长文、教程、对比分析和研究报告改写稿执行 L5；小红书和视频脚本按各自平台的短句、镜头和版式规则检查。

## 二、L1-L4 四层文章质检

### L1：硬性规则扫描（零容忍，发现就必须改）

**L1-1 禁用词**

全文扫描，出现任意一个必须替换：

| 禁用词 | 替换方向 |
|-------|---------|
| "说白了" | "坦率地说" / "其实就是" |
| "意味着什么？" / "这意味着" | "那结果呢" / "所以呢" / 直接说结论 |
| "本质上" | "说到底" / "其实" |
| "换句话说" | 删掉连接语，直接说结论或补充具体事实 |
| "不可否认" | 删掉，直接正面陈述 |
| "综上所述" / "总的来说" / "总而言之" | 删掉，直接给结论 |
| "首先...其次...最后" | 用自然转场词替代 |
| "值得注意的是" | 删掉，直接说要注意什么 |
| "不难发现" | 删掉，直接说发现了什么 |
| "显而易见" | 删掉，直接说 |
| "让我们来看看" / "接下来让我们" | 直接进入内容 |
| "在当今...时代" | 删掉，从具体事件切入 |
| "随着AI技术的发展" | 删掉 |
| "希望对大家有所帮助" | 删掉 |
| "如有不足之处，欢迎指正" | 删掉 |
| "具有重要意义" | 说出具体是什么意义 |
| "不说废话，直接上干货" | 删掉，直接开始 |

**L1-2 禁用标点**

| 禁用标点 | 替换方式 |
|---------|---------|
| 冒号 "：" | 用逗号代替，或重写句子结构 |
| 破折号 "——" | 用逗号/句号代替 |
| 双引号 "" / "" | 改用「」，或直接不加引号 |

**L1-3 结构使用边界**

- 不用 bullet point 代替论证。步骤、检查清单、并列选项和字段对比可以使用列表，但要说明这些信息如何影响读者的操作或判断。
- **不大量加粗**（超过2行的粗体几乎一定是过度结构化）
- 小标题用于帮助长文跳读和定位。1500-3000 字长文通常保留 3-6 个有信息量的小标题，不要每段加标题，也不要只写“背景”“分析”“总结”这类空标签。

**L1-4 具体工具名检查**

不能出现：
- "AI工具" → 写具体名称（Claude Code / LangGraph / image-this）
- "某个模型" → 写具体名称
- "相关技术" → 说清楚是什么技术

**L1 通过标准：以上四项扫描零命中。**

---

### L2：风格一致性检查

**L2-1 开头检查**
- [ ] 从一个具体的、当下的事件/场景切入（不是宏大叙事）
- [ ] 第一句话让人想看第二句
- [ ] 没有用教科书式开头

**L2-2 节奏检查**
- [ ] 有长短句交替（连续3句以上句式相似 = 节奏呆板）
- [ ] 有至少1处一句话独立成段的断裂效果
- [ ] 需要时用真实问题、操作结果或一句独立判断制造节奏；不强制添加疑问句
- [ ] 小标题数量与文章类型匹配，能帮助跳读，没有每段加标题或完全缺少导航

**L2-3 口语化检查**
- [ ] 语言符合 `content/_config/author-voice.md`；口语、疑问、自嘲只在作者真实材料支持时保留
- [ ] 没有为了显得像真人而硬塞口头禅、情绪或承认不足
- [ ] 没有纯书面语段落（通篇用逗号连接的长句）

**L2-4 禁用标点二次确认**
- [ ] 再次确认全文无冒号/破折号/双引号（改稿过程中容易重新引入）

**L2 通过标准：L2-1 全过；L2-2、L2-3 和 L2-4 仅检查文章真实材料与作者声音的一致性，不以添加口头禅、自嘲或疑问句作为通过条件。**

---

### L3：内容质量检查

**L3-1 观点有支撑**
- [ ] 每个核心观点有具体案例/数据/场景支撑
- [ ] 架构、工作流、插件或 Agent 文章至少有一项运行时证据：任务状态/依赖、Role/Skills/Context、Activity/日志、真实截图或可复现输出
- [ ] 没有纯论断的段落（只有观点没有依据）

**L3-2 知识是"随手掏"出来的**
- [ ] 知识以"聊着聊着顺手提到"的方式出现（不是"下面我来介绍"）
- [ ] 引用（工具/论文/历史）融入论述，不像单独插入的科普段落

**L3-3 有立场，不假装平衡**
- [ ] 文章有明确观点，不是"优点是A，缺点是B，总体来说还不错"
- [ ] 有明确作者判断；第一人称只在确有作者立场或第一手经历时使用，不用“有人认为”躲开判断

**L3-4 文章类型专项**（根据文章类型选对应项）

| 文章类型 | 重点检查项 |
|---------|----------|
| 工具教程型 | 有没有真实的使用场景？有没有踩坑记录？ |
| 实战分享型 | 有没有"亲自做了这件事"的叙事感？过程是否层层递进？ |
| 现象解读型 | 是否有"观察→好奇→分析→洞察"的推进？ |
| 方法论型 | 每节是否有可执行的行动建议？是否坦诚说明了学习成本？ |

**L3 通过标准：L3-1/2 必须全过，L3-3/4 过相关项。**

---

### L4：活人感终审（最主观、最重要）

先按 `.agents/skills/wechat-draft-editor/SKILL.md`（`wechat-draft-editor`）做一次结构级扫描，再通读全文。关键词扫描只能发现表面词汇，不能替代下面的判断。

重点检查：
- 同一个工具/项目是否被重复介绍，或前后两次宣布“我做了它”。
- 相邻段落是否重复同一因果链、例子或结论。
- 是否出现连续的“不是 A，而是 B”“不在 A，而在 B”式对仗。
- 是否有“这篇要讲什么”“有一点先说清楚”“接下来我们来看”这类报幕。
- 是否先宣布了结论或产品价值，后面又从头铺垫同一个问题。
- 是否每节都用工整金句、三段式或对仗句收束。
- 是否把“不是 A，而是 B”“难的不是……而是……”“不在于……而在于……”写成连续的判断腔。
- 是否反复用“错在让……”或“问题在于……”给句子贴标签，而没有描写实际发生过程。
- 口语是否来自真实经历，还是为了显得自然硬塞口头禅。

发现问题时，按“删重复 → 调顺序 → 打散结构 → 微调措辞”的顺序处理。不要直接做同义词批量替换。

通读全文，回答一个核心问题：

**"读完这篇，我感觉是一个真实的开发者/创作者在认真分享他的经历，还是 AI 在输出信息？"**

具体感知维度：

**L4-1 温度感**
- 情绪表达是体感记忆（"我当时就愣住了"）还是知识性描述（"我感到非常震撼"）？
- 有没有一处让你感觉"这个人真的经历过这件事"？

**L4-2 独特性**
- 这篇文章有没有"只有这个人才会写出来的角度"？
- 换个 AI 博主能写出差不多的版本吗？

**L4-3 姿态**
- 是"有经验的人分享踩坑心得"的姿态？
- 还是不小心滑入了"导师在教学生"的语气？

**L4-4 心流**
- 从头读，有没有哪里注意力断掉了？
- 有没有哪段逻辑跳跃需要回头理解？

**L4 通过标准：整体感觉"这像真人写的"。有任何一段"AI味太重"、只有抽象功能介绍、或图片只是装饰而未提供新证据，就需要返工。**

**L4 修复方法：**先判断问题属于重复、顺序、结构还是措辞，再想"如果我自己说这段话，我会怎么说"，重写。重复信息要删除或合并，逻辑顺序问题要移动段落，只有措辞问题才做局部改写。

## 三、L5 可读性检查

适用于公众号长文、知乎长文、教程、对比分析和研究报告改写稿。可读性不是把内容写浅，而是让读者知道自己正在读什么、为什么继续读，以及哪些信息可以带走。

### L5-1 阅读路径

- [ ] 标题能说清问题、对象或结果，不只写抽象主题
- [ ] 开头 150-300 字内交代场景、核心判断和阅读收益
- [ ] 有 3-6 个有信息量的小标题，或有同等清晰的自然分段结构
- [ ] 每个主要章节只回答一个问题，章节顺序能说出因果或决策关系
- [ ] 只扫标题和每节第一句，也能复述文章主线

### L5-2 段落与句子

- [ ] 普通段落大多为 2-5 句，没有连续多段挤成文字墙
- [ ] 没有超过约 150 个汉字、却只表达一个判断的长段落
- [ ] 连续三段抽象判断后有事实、案例、数据、代码、操作结果或反例
- [ ] 长句中的主语、动作和结论清楚，没有把五层条件塞进一句话
- [ ] 每一节结尾有判断、后果或下一步，不在段尾悬空

### L5-3 术语与材料

- [ ] 第一次出现的关键术语先解释用途，再给英文名或正式定义
- [ ] 事实、作者判断和不确定信息能分辨
- [ ] 每 500-700 字至少有一处可感知材料，不能只靠抽象观点推进
- [ ] 架构图、流程图或产品截图与正文共享同一事实基础，能说明状态、依赖、角色或数据流，不能只做抽象装饰
- [ ] 没有为了满足字数重复解释同一个概念

### L5-4 代码、表格与列表

- [ ] 代码块前说明它解决什么问题，代码块后只解释关键点
- [ ] 正文代码只保留读者需要复制或理解的部分，完整实现有明确去处
- [ ] 表格只保留会影响选择的维度，没有超过 6 列或单元格小作文
- [ ] 列表用于步骤、并列选项、检查清单或字段对比，没有替代论证
- [ ] 列表、表格和代码后有一句说明它对读者有什么用

### L5-5 快速读者模拟

请只读标题、小标题、每节第一句、代码说明和结尾，然后回答：

1. 我知道这篇在解决什么问题吗？
2. 我知道每一节为什么值得读吗？
3. 我能分辨事实、作者判断和待验证信息吗？

任一答案为“不能”，文章先返工阅读路径，不进入发布。

**L5 通过标准**：L5-1 必须全过；L5-2 至少 4/5 通过；L5-3 至少 3/4 通过；L5-4 至少 4/5 通过；L5-5 三问全能回答。
